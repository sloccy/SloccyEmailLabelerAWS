Classification model
Bedrock model used to label incoming emails. Sorted cheapest input cost first, unpriced models ("n/a") last. Standard is normal-latency processing, open to any Converse-capable model; Flex is a discounted, lower-priority tier open to any flex-capable model — higher latency, but still fast.
Prompt improver model
Bedrock model used for "Generate instruction" and "Improve rule". A smarter model here is fine since it runs infrequently. Same Standard/Flex tiers as classification — flex is discounted but lower-priority, which is fine for these occasional interactive calls.
Before showing an AI-suggested rule rewrite, replay it against the rule's stored example corpus using the classification model (never the improver) and show a pass rate — e.g. "27/30 correct". Adds one classify call per example in the validation sample below (fanned out concurrently), each time a suggestion is generated or regenerated; costs a fraction of a cent per suggestion on Nova Micro, more on a pricier classification model.
Improve rounds
How many improve→validate rounds one suggestion may run: after the first draft, if validation found mistakes, the improver sees exactly what it got wrong and tries again — up to this many rounds, stopping early on a perfect score or a round that doesn't beat the best one so far. Each extra round costs one more improve call plus a full validation pass. Has no effect while validation above is off — with nothing to score, only one round ever runs.
Example sample sizes
How many examples per verdict (missed it / wrongly caught / already correct) are curated from a rule's full history. Selection prioritizes examples that recurred after an earlier fix, then ones a human manually reviewed, then everything else — spread across senders rather than just the newest few. The improve set is what the AI rewrite prompt itself sees (small, since it costs prompt tokens); the validation set is what it's scored against afterward (larger is fine — it only costs classify calls, not tokens, and gives a much less noisy pass rate).

Reasoning suppression override
Reasoning-capable classification models (Qwen3, Nemotron, etc.) are told to skip chain-of-thought automatically, based on the selected model's family — this costs nothing to leave blank. Only set this if your model isn't recognized yet: enter its "reasoning off" soft-switch text (e.g. /no_think) and it overrides the automatic choice. Check the logs after a classify run for a "reasoning: suppressed=true/false" line to confirm it's working.
